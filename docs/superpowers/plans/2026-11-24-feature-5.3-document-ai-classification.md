# Feature 5.3 — Document AI Classification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Process a private, scan-approved document asynchronously and present AI OCR/classification suggestions to an admin without allowing AI to publish a document or mutate official taxonomy.

**Architecture:** Java owns persistent state, Kafka contracts, signed-URL issuance, validation, retries, and every submission-status transition. Python is a private Kafka worker: it downloads a short-lived URL, extracts text or conditionally runs OCR, produces schema-validated suggestions, and never exposes a client-facing classification endpoint. The existing React review page displays the resulting suggestions and lets admins retry failures.

**Tech Stack:** Spring Boot, JPA/Flyway, Spring Kafka, PostgreSQL, MinIO signed URLs; Python 3.12, FastAPI, Pydantic, Kafka, PyMuPDF/DOCX/PPTX extractors, OCR provider; React/TypeScript/TanStack Query.

**Spec:** `docs/superpowers/plans/2026-11-22-document-ai-classification.md`, implementing `docs/plans/phase_05.md` Feature 5.3.

## Global Constraints

- Only enqueue or process a run when `media.status = READY`.
- Keep the submission at `PENDING_PROCESSING` until Java accepts a valid completion; only Java may move it to `PENDING_REVIEW`.
- `classification_run_id` is unique; request and completion handling is idempotent.
- Reject malformed output, unknown taxonomy slugs, non-finite confidence, and confidence outside `[0,1]`.
- Suggested collections/tags reference existing taxonomy only; AI never writes `document_collection` or `document_tag`.
- AI cannot set `APPROVED`, `PUBLIC`, or grant a public download.
- The worker receives only a short-lived signed GET URL. Do not log OCR text, full signed URLs, document contents, object keys, or storage credentials.
- Retries are bounded and exhausted jobs remain inspectable through a dead-letter state/path.

## Review Focus

- A backend crash after upload completion still leads to publishing through the durable outbox.
- Duplicate, stale, or media-mismatched Kafka completions create no extra result and cannot advance a wrong submission.
- A text PDF skips OCR; a scanned PDF uses OCR; corrupt, oversized, and timed-out inputs fail safely.
- A direct browser request cannot start a classification job or access worker credentials.
- AI failure leaves the document private and provides an admin retry path.

## Self-Review

- The plan changes the current premature `PENDING_REVIEW` transition in `DocumentService.completeUpload`.
- Every Kafka payload is defined before a producer or consumer depends on it.
- Python owns extraction/classification only; Java owns durable state, validation, official taxonomy, and visibility/status decisions.
- The UI is introduced only after a persisted, validated result and retry contract exist.
- All Feature 5.3 requirements are covered: ready gating, OCR/model provenance, confidence validation, retry/idempotency, private storage, admin review, and no AI publication.
